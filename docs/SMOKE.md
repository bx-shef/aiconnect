# Смок-прогон на тестовом портале

> Last reviewed: 2026-09-28

`pnpm smoke` — живая проверка REST на **тестовом** портале. Юнит-тесты (`pnpm test`) проверяют
правила на подставных данных; смок — что портал отвечает так, как ждёт код, тем же b24jssdk.
В CI не запускается.

Сейчас набор маленький: формы `profile`, `scope` и `ai.engine.list` (`smoke/rest.smoke.ts`). Предметная часть
шаблона (засев сделок, счетов, задач, BitrixGPT) удалена на этапе 0. Следующие этапы добавят сюда
регистрацию провайдера и сквозной «запрос → ответ» (`docs/PLAN.md`, этап 4).

Подход — по образцу живых проверок ai-price-import (`scripts/lib/envFile.mjs`,
`testPortalGuard.mjs`), вместе с их граблями (см. «Окружение»).

## Когда запускать

- Поменялся запрос к порталу или разбор его ответа.
- Обновился b24jssdk.
- Время от времени: портал меняется без нас.

## Окружение

Git-ignored файл `.env.b24test` в корне (шаблон — `.env.b24test.example`), или другой путь в
`SMOKE_ENV_FILE`:

```bash
B24_HOOK=https://<тестовый-портал>.bitrix24.by/rest/<id>/<код>/   # входящий вебхук администратора
```

- **Адрес портала берётся только из файла**, переменная окружения `B24_HOOK` не читается. В
  оболочке может жить `B24_HOOK` другого, боевого портала: в ai-price-import так уже уходили не
  туда.
- Из файла берётся последнее вхождение ключа, кавычки снимаются, `export KEY=` понимается.
  Закомментированный `#KEY=` и ключ-суффикс (`OLD_B24_HOOK`) не подхватываются.
- **Страж.** Работать можно только с порталом из `smoke/lib/env.ts → TEST_PORTALS`. Другой домен —
  только с явным согласием, где домен назван руками: `B24_SMOKE_YES_TARGET=<домен> pnpm smoke`.
  В списке — `b24-ypkv9c.bitrix24.by`, тестовый портал aiconnect (владелец, 2026-09-28).
- Секрет вебхука в вывод не попадает: ошибки несут метод и текст портала, адреса вырезаются
  (`smoke/lib/portal.ts`).

Нет файла или в нём нет `B24_HOOK` — все проверки пропускаются.

```bash
pnpm smoke                                     # .env.b24test из корня
SMOKE_ENV_FILE=/path/.env.b24test pnpm smoke   # файл в другом месте
```

## Что проверяет

| Набор | Что проверяет |
|---|---|
| `rest.smoke.ts` | `profile`: `ADMIN` — логическое, `ID` — строка (на этом стоит строгая проверка в `frameAuth.ts`); `scope`: массив строк (его сверяет страница установки); `ai.engine.list`: массив, у записей есть `code`, `category`, `completions_url` (замер — `docs/RESEARCH.md`) |

## Как читать красное

- **Красный `rest.smoke.ts`** — портал отвечает иначе, чем записано в `docs/REST_METHODS.md`.
  Замерьте, поправьте код и строку реестра.

## Как добавить проверку

- Проверка формы ответа — в `rest.smoke.ts`. Ожидание пишется **независимо**, а не вызовом той же
  функции, что в коде: иначе проверка повторит ошибку кода.
- Данные, которые смок создаёт в портале, — с меткой прогона в названии, чтобы их можно было найти.
