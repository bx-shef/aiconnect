# Прогоны шпиона: облако `.by`, облако `.ru`, коробка — промпт для Claude в Chrome

> Last reviewed: 2026-11-01

Три прогона одним сценарием. Цель — записать, что BitrixGPT присылает стороннему движку в
каждом сценарии (bx-shef/aiconnect#19 → bx-shef/toolsai-mcp#155). Агент работает в браузере
владельца, вошедшего в портал администратором, и отдаёт текстовый отчёт. Факты из отчёта идут в
`docs/PROTOCOL.md`, полный журнал (облако) — выгрузкой JSON, в git и issue его не кладём.

| Прогон | Где записывается запрос | Звонки |
|---|---|---|
| A. Облако `.by` (`b24-k82h1m.bitrix24.by`) | шпион `aiconnect`, полный журнал | автозапуска нет — ручной запуск в карточке |
| B. Облако `.ru` | то же | автозапуск — только по подписке «BitrixGPT + Маркетплейс»; иначе ручной |
| C. Коробка (стенд bx-shef/toolsai-stand) | приёмник `spy_capture.php` на стенде | автозапуск по настройкам воронки (зона лицензии) |

Справка Битрикс24 «BitrixGPT в CRM: как настроить обработку звонков, чатов и писем»
(helpdesk.bitrix24.ru/open/29087800): «Автоматический запуск работает только в зоне ru по
подписке BitrixGPT + Маркетплейс. Ручной запуск можно использовать во всех доменных зонах — он
расходует запросы к BitrixGPT».

## Подготовка — облако (A и B)

1. Приложение стоит на портале локальным приложением (`docs/DEPLOY.md` §2, «Без Маркета»):
   права `ai_admin`, `user_brief`, `telephony`, `crm`. Из кабинета разработчика установка требует
   подписку Маркет Плюс.
2. На сервере в `.env`: домен портала — в `B24_SPY_PORTALS` (через запятую), `B24_SPY_FULL=1`;
   затем `make prod-up`. Страница шпиона показывает «Полный текст: вкл».
3. Тестовый звонок — с компьютера, где есть Node 22 и этот репозиторий, вебхуком администратора
   портала (права `crm`, `telephony`):
   ```bash
   B24_WEBHOOK=https://<портал>/rest/<id>/<ключ>/ node scripts/spy-call.mjs calls
   ```
   Скрипт создаёт лид, входящий звонок как от АТС и прикладывает запись (синтетический русский
   диалог на 29 с, `scripts/fixtures/call-won-supply.mp3`); печатает ссылку на лид. Вебхук — только
   в окружении, в чат и в git не попадает. После прогонов вебхук удалить на портале.

## Подготовка — коробка (C)

Приложение `aiconnect` облачное: на коробке нет REST `ai.engine.register`, и установка приложения
не сохраняется (`docs/B24_EVENTS.md`). Поэтому на стенде запросы ловит отдельный приёмник, а
движки регистрирует PHP штатным `\Bitrix\AI\ThirdParty\Manager::register()` (так же делает
`shef.toolsai`, `lib/engine/registrar.php`). **Не проверено на стенде** — первый прогон покажет.

1. Приёмник — файл `/var/www/html/bitrix/tools/spy_capture.php` в контейнере `portal`:
   ```php
   <?php
   // Protocol spy for the box: stores each request body as is, answers 202 (GET — 200 for the
   // registration check). auth and callback URLs are masked; files go outside the web root.
   if ($_SERVER['REQUEST_METHOD'] !== 'POST') { http_response_code(200); echo '{"ready":true}'; return; }
   $raw = file_get_contents('php://input', false, null, 0, 16 * 1024 * 1024);
   $body = json_decode($raw, true);
   if (is_array($body)) {
       foreach (['auth'] as $k) if (isset($body[$k])) $body[$k] = '<masked>';
       foreach (['callbackUrl', 'errorCallbackUrl'] as $k) if (isset($body[$k])) $body[$k] = '<url:' . parse_url((string)$body[$k], PHP_URL_HOST) . '>';
   }
   $dir = '/var/spy-capture';
   @mkdir($dir, 0700, true);
   $label = @file_get_contents($dir . '/SCENARIO') ?: '';
   file_put_contents($dir . '/' . date('Ymd-His') . '-' . bin2hex(random_bytes(3)) . '.json', json_encode([
       'at' => date('c'), 'scenario' => trim($label), 'category' => $_GET['c'] ?? '',
       'contentType' => $_SERVER['CONTENT_TYPE'] ?? '', 'size' => strlen($raw),
       'body' => is_array($body) ? $body : (preg_match('/^[\w.%\[\]-]+=/', $raw) ? '[form body not kept]' : '[raw not kept]'),
   ], JSON_UNESCAPED_UNICODE | JSON_PRETTY_PRINT));
   http_response_code(202);
   header('Content-Type: application/json');
   echo '{"result":"OK"}';
   ```
   Ответа модели нет: задание у ядра заканчивается по `ttl` ошибкой — для записи запроса этого
   достаточно.
2. Регистрация движков «TEST <категория>» — один раз (`docker compose exec portal php -r '…'` из
   корня сайта, после `require 'bitrix/modules/main/include/prolog_before.php'` и
   `\Bitrix\Main\Loader::includeModule('ai')`):
   ```php
   foreach (['text', 'image', 'audio', 'call', 'vision', 'classify'] as $c) {
       \Bitrix\AI\ThirdParty\Manager::register([
           'name' => "TEST $c", 'code' => "sh_spy_box_$c", 'category' => $c,
           'completions_url' => 'https://<внешний адрес стенда>/bitrix/tools/spy_capture.php?c=' . $c,
           'settings' => [],
       ]);
   }
   ```
   Снять после прогона — `Manager::unRegister(['code' => "sh_spy_box_$c"])` для каждой категории.
3. Метка сценария — `echo chat.deal-stage > /var/spy-capture/SCENARIO` в контейнере перед
   сценарием. Записи — `ls /var/spy-capture`, файл — `cat`.
4. Звонок — `toolsai/docker/stand/test-call.sh` (тон) или демо-звонки стенда (озвученные диалоги,
   toolsai-stand README «демо»); автозапуск — по настройкам воронки, вне зоны `ru` шаг
   «Расшифровать» по умолчанию выключен (toolsai `docs/private/00-research.md`).

## Промпт

Заменить `<ПОРТАЛ>` на адрес портала (`https://b24-k82h1m.bitrix24.by`, адрес `.ru`, адрес
стенда) и `<ГДЕ ЗАПИСИ>`:
- облако — «страница шпиона: Приложения → aiconnect → Шпион протокола»;
- коробка — «записи смотрит владелец в терминале; после каждого сценария скажи мне его метку и
  жди моего ответа, пришла ли запись».

```text
Ты проверяешь, что BitrixGPT отправляет стороннему AI-движку в разных сценариях портала
Битрикс24 <ПОРТАЛ>. Я вошёл администратором в этом браузере. Работай только в этом портале, в
одной новой вкладке. Меняй только то, что сказано в шагах, и в конце верни всё как было.

Как это устроено: в портале зарегистрированы тестовые движки «TEST text», «TEST image»,
«TEST audio», «TEST call», «TEST vision», «TEST classify». Запрос к такой «модели» записывается
(<ГДЕ ЗАПИСИ>) и получает ошибку. Модели за ними нет: «Ошибка на стороне провайдера модели AI»
в портале — ожидаемый результат и признак того, что запрос ушёл к нам.

Особенности (уже замечены):
- Кнопка «Шпион протокола» появляется через несколько секунд; нет — перезагрузи, подожди
  15 секунд; после двух перезагрузок нет — скриншот и стоп.
- Выбор модели в настройках BitrixGPT иногда не сохраняется с первого «Сохранить». После каждого
  сохранения перезагружай и проверяй; не сохранилось — «Сохранить» ещё раз.
- Escape закрывает всю панель настроек — выпадающие списки закрывай кликом.
- Инструмент браузера иногда отвечает ошибкой — повтори действие.

Метка сценария: перед каждым сценарием ставь метку из списка ниже.
- Облако: на странице шпиона поле «Сценарий» → вписать метку → «Сохранить метку»; проверь
  «Сейчас: <метка>».
- Коробка: напиши мне метку и жди, пока я отвечу «готово».

Шаги:

1. ПОДГОТОВКА. Облако: страница шпиона; в «Провайдерах» все 6 — «зарегистрирован» (нет —
   «Зарегистрировать все»), «Полный текст: вкл», режим ответа — «ошибкой». Запомни число
   «Пойманных запросов». Скриншот.

2. ЭТАЛОН. Настройки → Настройки BitrixGPT: запиши ВСЕ переключатели и ВСЕ списки «Выберите
   модель AI для …» (что выбрано, какие TEST есть). Затем CRM → Лиды → ⚙ → «Настройки BitrixGPT»
   и CRM → Сделки (общая воронка) → ⚙ → «Настройки BitrixGPT»: запиши для каждого блока
   (Расшифровка звонков, Резюме, Заполнение полей, Создание дел) режим «Звонки/Чаты/Почта» и
   метку справа («Не работает» или другая). Это эталон для возврата.

3. ВКЛЮЧЕНИЕ. Включи «Чат с BitrixGPT», в «Работе с текстами» — «Задачи». Во ВСЕХ списках, где
   есть «TEST …», выбери соответствующий TEST (текст — TEST text, изображения — TEST image,
   расшифровка — TEST audio). Сохрани, перезагрузи, сверь.

4. СЦЕНАРИИ. Для каждого: метка → действие → ответ портала дословно → проверка записи.
   a) chat.question — новый чат с BitrixGPT: «Что будет, если перевести сделку из успешной
      стадии в начальную?»
   b) chat.followup — в том же чате: «А если в сделке есть оплаченный счёт?»
   c) tasks.write — новая задача → BitrixGPT в описании → «Напиши описание задачи: подготовить
      КП по насосам». Задачу НЕ сохранять («Отменить»).
   d) feed.write — Лента → новое сообщение → BitrixGPT → «Поздравь отдел продаж с планом».
      Сообщение НЕ публиковать.
   e) image — где есть генерация изображения (лента или чат с BitrixGPT): «Насос на складе».
      Не публиковать.
   f) call.manual — открой лид из ссылки, которую я дал (тестовый звонок). В деле звонка нажми
      кнопку справа от плеера («→A» / «Расшифровать») или «CoPilot» в деле. Подожди 2 минуты.
      Запиши, что показала карточка.
   g) call.auto — только если я скажу, что сделал второй звонок: открой его лид, ничего не
      нажимай, подожди 3 минуты, запиши, появилась ли работа CoPilot сама.
   После каждого: облако — «Обновить» на странице шпиона, раскрой новые строки (клик), нажми
   «Показать полностью»; коробка — спроси меня.

5. ЗАПИСЬ ПО КАЖДОМУ ЗАПРОСУ (что переписать в отчёт):
   - время · метка · категория · размер · callback (URL-хост и статус);
   - Content-Type, ключи верхнего уровня;
   - короткие поля целиком: category, promptCategory, bx_module, payload_provider, payload_raw
     (если короткое), payload_markers, max_tokens, context (кратко);
   - prompt и payload_role: первые 1500 знаков и полная длина;
   - для audio/call: где запись звонка (поле, URL-хост, формат), есть ли текст;
   - есть ли что-то про инструменты/функции (tools, functions, actions) и данные CRM.
   Не переписывай значения auth и адреса callback (они и так скрыты).

6. ВЫГРУЗКА (облако). На странице шпиона — «Скачать журнал» (все сценарии). Скажи, скачался ли
   файл и его имя.

7. ВОЗВРАТ. Верни все списки и переключатели к эталону шага 2 (и в настройках BitrixGPT, и в
   CRM), сохрани, перезагрузи и сверь по пунктам. На странице шпиона метку очисти (пусто →
   «Сохранить метку»). «Снять все» и «Очистить журнал» НЕ нажимай.

Отчёт (по-русски, коротко):
- первой строкой: какие сценарии дошли до движка (метка → да/нет → категория);
- таблица эталона (шаг 2) и таблица «сценарий → ответ портала → запрос пришёл → категория, размер»;
- по каждому запросу — данные из шага 5;
- что сделал не так, как в шагах, и почему; ошибки дословно, без догадок о причинах;
- подтверждение шага 7.

Ограничения: не вводи и не показывай пароли и ключи; не открывай вебхуки и раздел
«Разработчикам»; не удаляй и не переустанавливай приложения; не устанавливай модули; не
сохраняй задачи, сообщения ленты, письма; не меняй записи CRM, кроме нажатия «Расшифровать» в
шаге 4f; если что-то просит подтверждения, которого нет в шагах, — остановись и спроси меня.
```
