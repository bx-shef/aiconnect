# Протокол BitrixGPT → провайдер: замеры

> Last reviewed: 2026-11-01

Что на самом деле присылает Битрикс24 на `completions_url` и как принимает ответы. Заполняется по
итогам прогона шпиона протокола (этап 1 `docs/PLAN.md`, страница `/spy`). Каждая строка — замер:
дата, портал, сценарий в интерфейсе, что пришло. Что было известно до замеров — `docs/RESEARCH.md`.

**Статус: первый прогон 2026-11-01** — портал `b24-k82h1m.bitrix24.by` (бесплатный облачный, .by),
приложение локальное, шпион из `558111b`; отчёт — bx-shef/aiconnect#19. Строки шпион обрезает до
500 знаков, поэтому длинные поля известны по началу и длине.

Установка из кабинета разработчика («Протестировать») на этом портале требует подписку Маркет Плюс
(`SUBSCRIPTION_REQUIRED`) — ставили локальным приложением.

## Как снимать

0. Портал должен быть в `B24_SPY_PORTALS` на сервере (`docs/DEPLOY.md` §4), иначе страница скажет
   «Шпион выключен для этого портала».
1. Администратор открывает «Приложения» → aiconnect → «Шпион протокола» → «Зарегистрировать все».
   Появляются провайдеры «TEST text», «TEST image», «TEST audio», «TEST call», «TEST vision»,
   «TEST classify» (коды `sh_aiconnect_spy_<category>`).
2. В настройках BitrixGPT выбрать «TEST …» там, где это возможно, и сделать запрос в интерфейсе.
3. На странице шпиона — «Обновить»: запрос появляется в «Пойманных запросах» (строки длиннее 500
   символов обрезаны, `auth` показан без значений — только ключи и длины).
   Перед сценарием задайте **метку** (поле «Сценарий», например `chat.deal-stage`; латиница,
   цифры, `.` `_` `-`, до 64 знаков, хранится строчными; пусто — снять): она ставится на
   следующие запросы. С `B24_SPY_FULL=1` на сервере запрос хранится целиком — «Показать
   полностью» в строке, «Скачать журнал» (JSON, можно по одной метке), «Очистить журнал»;
   `auth` и адреса callback скрыты всегда. Журнал в git и в issue не кладём — в репозиторий
   только выжимка своими словами.
4. Режим «Отвечать ошибкой» (по умолчанию) — портал получает error callback с
   `api_request_completed: false`; «Отвечать тестовым текстом» — успешный callback.
5. После прогона — «Снять все».

Проверку в браузере может сделать AI-агент по промпту из `docs/SPY_CHECK.md`.

Шпион хранит последние 50 запросов портала на нашем сервере; удаление приложения их стирает. В
журнал сервера пишется только структура (категория, размер, ключи), не тексты.

## Форма запроса по категориям

Для каждой категории — ключи верхнего уровня, `Content-Type`, размер, форма `prompt`, что в
`auth`, где лежат `callbackUrl` / `errorCallbackUrl` (хост портала или другой).

### text

Оба запроса — `Content-Type: application/json`; `auth` — строковые поля (шпион показывает только
длины); callback — `errorCallbackUrl` (режим «ошибкой»), ответ портала `200`, пользователю —
«Ошибка на стороне провайдера модели AI».

| Поле | Чат с BitrixGPT | Задачи |
|---|---|---|
| ключи сверх общих¹ | — | `promptCategory: "tasks"`, `bx_module: "tasks"`, `bx_context`, `bx_history`, `bx_history_group_id`, `bx_analytic`, `max_tokens: 1500`, `response_format` |
| `prompt` | блоки `<<<CONTEXT>>>` (имя чата), `<<<HISTORY>>>`, `<<<CURRENT_MESSAGE>>>` (время, автор, текст), `<<<INSTRUCTIONS>>>`; 560 знаков | шаблон «Write in <язык>… Follow the request…» |
| `payload_raw` | совпадает с `prompt` | `"zero_prompt"` |
| `payload_provider` | `"text"` | `"prompt"` |
| `payload_role` | роль BitrixGPT, 6 716 знаков | роль BitrixGPT, 2 167 знаков |
| `payload_markers` | `{language}` | `{user_message, …}` |
| `context` | `[]` | — |
| инструменты | нет `tools` / `functions` / `actions`, полей CRM нет | — |

¹ Общие: `prompt, payload_raw, payload_provider, payload_role, context, payload_markers,
payload_prompt_text, auth, category, ttl, callbackUrl, errorCallbackUrl`.

Чат шлёт стороннему движку только текст разговора и роль — данных сделки и описаний инструментов
в запросе нет (в видимой части; хвосты `prompt` и `payload_role` обрезаны).
