# Протокол BitrixGPT → провайдер: замеры

> Last reviewed: 2026-09-28

Что на самом деле присылает Битрикс24 на `completions_url` и как принимает ответы. Заполняется по
итогам прогона шпиона протокола (этап 1 `docs/PLAN.md`, страница `/spy`). Каждая строка — замер:
дата, портал, сценарий в интерфейсе, что пришло. Что было известно до замеров — `docs/RESEARCH.md`.

**Статус: шпион готов, прогона ещё не было.** Ниже — что заполнить.

## Как снимать

0. Портал должен быть в `B24_SPY_PORTALS` на сервере (`docs/DEPLOY.md` §4), иначе страница скажет
   «Шпион выключен для этого портала».
1. Администратор открывает «Приложения» → aiconnect → «Шпион протокола» → «Зарегистрировать все».
   Появляются провайдеры «TEST text», «TEST image», «TEST audio», «TEST call», «TEST vision»,
   «TEST classify» (коды `sh_aiconnect_spy_<category>`).
2. В настройках BitrixGPT выбрать «TEST …» там, где это возможно, и сделать запрос в интерфейсе.
3. На странице шпиона — «Обновить»: запрос появляется в «Пойманных запросах» (строки длиннее 500
   символов обрезаны, `auth` показан без значений — только ключи и длины).
4. Режим «Отвечать ошибкой» (по умолчанию) — портал получает error callback с
   `api_request_completed: false`; «Отвечать тестовым текстом» — успешный callback.
5. После прогона — «Снять все».

Проверку в браузере может сделать AI-агент по промпту из `docs/SPY_CHECK.md`.

Шпион хранит последние 50 запросов портала на нашем сервере; удаление приложения их стирает. В
журнал сервера пишется только структура (категория, размер, ключи), не тексты.
